轻拾 · 照片与视频去重

开始使用
1. 解压便携包，双击 DuplicateMediaApp.exe。不需要命令行、源码或安装程序。
2. 点“选择文件夹”，或在输入框中粘贴完整路径，点“开始扫描”。应用会递归扫描子目录；此过程不移动、改写或删除媒体文件。
3. 查看重复组。每组按完整路径排序，默认建议保留第一份，勾选其余副本。这只是位置建议，不表示画质更好或拍摄时间更早。可逐个勾选，也可按建议重选或取消所有勾选。
4. 想核对位置时，选中一行，点“复制路径”或“在资源管理器中定位”。鼠标停在路径上也可查看全文。可将清单导出到一个新的 CSV 文件；文件使用带 BOM 的 UTF-8，包含完整路径、组号、勾选状态、建议、字节数、本地修改时间和完整 SHA-256。
5. 点“清理到回收站”，核对数量和总大小，再决定是否确认。整组勾选会被拒绝并提示组号。只想生成清单时，无需执行这一步。

哪些算重复？
按文件大小 → 首、中、尾抽样 → 完整 SHA-256 核对。即使文件名、扩展名不同，也能找到相同的文件内容；相同大小或抽样匹配本身不算重复。不解码媒体，不判断画面相似，不把连拍、转码或重新压缩的文件当作相同内容。
照片：JPG/JPEG/JPE、PNG、HEIC/HEIF、WebP、TIFF/TIF、GIF、BMP、DNG、RAW、CR2/CR3、NEF、ARW、ORF、RW2、RAF、PEF、SRW。
视频：MP4、MOV、AVI、MKV、WMV、M4V、MTS/M2TS、WebM、TS、MPG/MPEG、3GP/3G2、FLV、VOB。扩展名不区分大小写。

回收与还原
• 清理时重新读取保留副本和勾选文件的全部内容，核对扫描记录，并在处理本组期间锁住已验证的保留副本。请不要同时用其他程序改名、同步或替换这些文件；Windows 的路径操作不是整个文件夹的原子事务。
• 使用 Windows Shell 专门的回收接口。如果没有可验证的保留副本、文件变更/丢失/被占用、回收站不可用或系统拒绝操作，该项不会按成功处理。不请求永久删除，也不会自动清空回收站。
• 网络位置可尝试只读扫描，但不执行回收。跳过回收站、系统卷信息目录、重解析点和离线占位文件；不会跟随目录链接遍历其他位置。与保留项指向相同文件标识的硬链接/别名也不清理。Windows Shell 不支持某个长路径时，回收步骤可拒绝该文件，即使只读扫描可以读取它。
• 扫描和清理都可取消。系统 I/O 结束可能需要一点时间。取消扫描不显示部分结果；取消清理只停止后续操作，已经回收的文件不会自动还原。仅确认回收成功的行会从清单移除，失败项和保留项仍在。
• 还原：打开 Windows 回收站，按文件名及“原位置”核对，右键对应条目 →“还原”。已清空或被系统策略清除的条目不能用此方法还原；建议重要资料另有备份。
• 列表的 KB/MB/GB 按 1024 进位，勾选总量是文件逻辑大小。移入回收站不等于立即释放磁盘空间。

运行环境与日志
目标为 Windows 10 22H2（x86/x64）及 Windows 11 x64 桌面，需 .NET Framework 4.8 或 4.8.1。不是 .NET SDK 或 .NET Core 应用。EXE 为 AnyCPU，默认按系统架构运行。普通用户权限即可，无需网络或媒体编解码器。实际测试环境与未覆盖的组合见《验收报告》。
“查看本次日志”可打开含路径及原因的记录。也可将以下路径粘贴到资源管理器地址栏：
  %LOCALAPPDATA%\DuplicateMediaApp
  startup.log：启动、窗口显示、异常与退出；如该日志目录不可写，启动日志会尝试写到 %TEMP%\DuplicateMediaApp-startup-进程号.log。
  scan-*.log：本次扫描路径、跳过原因、阶段计时。
  clean-*.log：回收结果、保留路径或失败原因、取消后的统计。
日志和 CSV 含完整文件路径，仅存在本机；对外提供前请注意隐私。
若 EXE 在进入程序前即被阻止，可能没有启动日志。请联系 IT 查看 Windows 事件查看器中的应用程序、AppLocker 或 CodeIntegrity 记录，核对运行时和组织的软件签名要求。本版未附企业签名；不要关闭安全软件或绕过策略。
